02 · How my team ships

I turned our engineering process into agents.

At Oro Money I designed the Claude-based agent workflow the whole engineering team now uses. We brought in TDD by writing evals first, so every agent works against a clear bar before any UI exists.

  1. 01

    Test agent

    Reads the Linear ticket and acceptance criteria, studies the current system, and writes the evals and test cases first.

  2. 02

    Figma agent

    Takes a Figma link, reuses existing components where they fit, and builds the UI with placeholder data.

  3. 03

    API agent

    Wires up the real APIs and runs the evals from step one against them.

Same idea, my own product

PromptSight is built by an agent team I designed.

An architect agent plans and splits the work. A QA agent writes failing tests first. A developer agent builds each task in its own worktree. Three reviewers check the tests, the UI against the design, and the code, in parallel, and nothing merges until all of them pass. Failures go back to the same developer; after three rounds, they come to me.

40 pull requests shipped in four weeks
